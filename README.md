# Баланс — домашняя бухгалтерия

Локальное веб-приложение для домашнего ПК и устройств в домашней сети. Python, Flask, Waitress и SQLite; интерфейс на русском языке с тёмной темой и адаптацией к телефону

## Запуск на Linux

Требуется Python 3.11 или новее. Проверено на Python 3.14.

```bash
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
python main.py
```

При первом запуске создаётся `config.toml`, и программа останавливается с подсказкой. Откройте файл и задайте свой пароль:

```toml
[auth]
password = "ваш пароль"
```

Снова выполните `python main.py`. На сервере откройте **http://127.0.0.1:8080**. На телефоне или другом домашнем устройстве — **http://локальный-IP-сервера:8080**, подключившись к той же сети. Локальные адреса Linux-компьютера можно посмотреть командой `ip -brief address`: нужен адрес домашнего сетевого интерфейса, например `192.168.1.20`. Если настроен брандмауэр, разрешите входящий TCP-порт 8080 для домашней сети

Остановка: Ctrl+C. При следующих запусках достаточно активировать окружение и выполнить `python main.py`. Либо из любой папки вызвать `.venv/bin/python /полный/путь/к/main.py`, указав полный путь и к Python окружения. Docker и сборка JavaScript не нужны.

## Конфигурация и вход

Пример всех настроек – `config.example.toml`. `config.toml` и папка `data/` исключены из Git. Пустой пароль разрешён. Пароль хранится открытым текстом в конфигурации по согласованному требованию; приложение автоматически создаёт файл с правами `600`. Для строк TOML с обратными слешами удобно использовать одинарные кавычки. `server.host = "0.0.0.0"` разрешает подключение по домашней сети, `"127.0.0.1"` — только с сервера. Порт по умолчанию – 8080. Изменения конфигурации применяются после перезапуска.

Используется общий пароль и свободное переключение профилей. У сессии **нет срока истечения на сервере**. Она хранится в SQLite и переживает перезапуск. Выход отзывает сессию текущего браузера, смена пароля и перезапуск — все старые сессии. Браузер может самостоятельно ограничить срок хранения cookie или удалить их; тогда потребуется войти снова. Выход доступен в боковом меню на ПК и в настройках профиля на любом устройстве.

Защита входа включает ограничение попыток (5 за 15 минут с одного IP), защиту форм от CSRF и случайные токены сессий, хранимые в базе в виде хешей. По согласованному решению приложение работает по **HTTP**: соединение не шифруется. Оно предназначено для домашней сети, без публикации порта в интернете.

## Учёт

- У каждого профиля свои операции, категории, теги и начальный капитал в RUB, USD и EUR. Валюты учитываются отдельно; конвертация оформляется записью «Трансфер».
- Баланс каждой валюты: начальный капитал + доходы − расходы + получение по трансферам − списание по трансферам. Изменение начального капитала сразу пересчитывает баланс и не создаёт запись в журнале. Начальный капитал и рассчитанный баланс могут быть отрицательными.
- Операция содержит тип, положительную сумму с точностью до двух знаков, валюту, дату и время, обязательный комментарий, категорию и любое количество тегов. Денежные значения хранятся целыми копейками/центами.
- Трансфер — одна запись с исходной и получаемой валютой и двумя положительными суммами. Валюты должны различаться. Доступны ввод двух сумм с вычислением курса и ввод суммы списания с курсом «1 единица исходной валюты = N единиц получаемой». Курс задаётся пользователем, до 8 знаков после запятой; сумма получения округляется до копейки/цента, половины — вверх. Обе суммы сохраняются точно, а введённый курс сохраняется для повторного редактирования. Редактирование или удаление трансфера пересчитывает обе стороны сразу. Отрицательный остаток разрешён.
- Дата и время задаются по часовому поясу сервера. Ввод задним числом разрешён, будущее запрещено серверной проверкой. На форме дата и время по умолчанию соответствуют моменту её открытия.
- Категории и теги общие для всех типов операций внутри профиля. «Без категории» — постоянная категория по умолчанию; её нельзя переименовать или удалить. При удалении другой категории её записи переходят в «Без категории». Удаление тега убирает связи с операциями.
- Журнал поддерживает редактирование, удаление, поиск по комментарию и фильтры по типу, валюте, категории, нескольким тегам и датам включительно. При выборе нескольких тегов запись должна содержать их все; дополнительные теги допускаются. Фильтр валюты находит трансферы, в которых она списывается или получается. Сначала отображаются более поздние операции.
- Статистика за календарный день, последние 7 дней включительно по выбранную дату, месяц, год или произвольный диапазон дат показывает доходы, расходы, разницу и разбивку по категориям и тегам для выбранной валюты. Обе даты произвольного периода включаются целиком. Начальный капитал в доходы статистики не входит. Трансферы показываются отдельно как «Списано» и «Получено» и не входят в доходы, расходы, их разницу и разбивки по категориям/тегам. Операция с несколькими тегами учитывается в каждом из них; суммы по тегам могут пересекаться.
- Удаление операции или профиля необратимо. Интерфейс запрашивает подтверждение. Профиль удаляется вместе с его журналом, категориями, тегами и капиталом.

## Данные и резервная копия

По умолчанию данные находятся в `data/budget.sqlite3` рядом с `main.py`, независимо от текущей папки запуска. Путь меняется в `[storage] database`.

Для ручной резервной копии остановите приложение и скопируйте файл базы в безопасное место. Для восстановления при остановленном приложении замените файл базы копией. После восстановления также возвращаются сохранённые в копии сессии; при необходимости смените пароль и перезапустите приложение.

## Проверка

```bash
source .venv/bin/activate
python -m unittest discover -s tests -v
```

Тесты используют временные базы и не изменяют пользовательский журнал. Проверяются расчёты, даты, валюты, статистика, CRUD, изоляция профилей, внешние ключи, сессии, смена пароля, CSRF, экранирование HTML и ограничение входа.

Для Pyright/BasedPyright добавлен `pyrightconfig.json`: анализируются приложение и тесты в стандартном режиме, зависимости ищутся в `.venv` проекта. Предупреждения о неиспользуемых импортах и избыточных проверках типов включены явно. Конфигурация подходит и для расширения BasedPyright в VS Code; перед анализом необходимо установить зависимости по инструкции запуска.

JavaScript с JSDoc проверяется установленным TypeScript без сборки и создания файлов:

```bash
tsc --project jsconfig.json
```

Структура: `main.py` — запуск; `app/config.py` — конфигурация; `app/__init__.py` — страницы, вход и сессии; `app/domain.py` — правила учёта; `app/db.py` и `app/schema.sql` — SQLite; `app/templates/` и `app/static/` — интерфейс; `tests/runtime_server.py` — сервер для HTTP-теста.
