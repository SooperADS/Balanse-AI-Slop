# Памятка разработчика

## Структура и запрос

| Файл | Ответственность |
| --- | --- |
| `main.py` | Корень проекта, загрузка настроек, запуск Waitress |
| `app/__init__.py` | Общий экземпляр `APP`, маршруты, авторизация, CSRF, шаблонные фильтры |
| `app/config.py` | TOML, проверка настроек, хеш проверки пароля и отпечаток для сессий |
| `app/db.py` | Соединение SQLite на контекст Flask и его закрытие |
| `app/domain.py` | Валидация, операции с журналом, баланс, периоды и статистика |
| `app/schema.sql` | Таблицы, ограничения и индекс журнала |
| `app/templates/` | Jinja-страницы; `macros.html` и `statistics.html` — общие компоненты |
| `app/static/` | Стили и обычный JavaScript с JSDoc, без сборки |
| `tests/` | Проверки учёта и конфигурации; `runtime_server.py` — дочерний HTTP-сервер |

`init(config_obj)` применяет настройки и создаёт отсутствующие таблицы. Это не миграция и не сброс базы. Для запроса `authenticate()` фиксирует `g.now`, проверяет сессию и CSRF; `select_profile()` выбирает профиль. Обработчик вызывает функции домена и формирует HTML. После ответа добавляются защитные заголовки, затем соединение БД закрывается.

Для чтения и записи нужен контекст Flask. `db.get()` включает внешние ключи и возвращает `sqlite3.Row`. Записи выполняются через `with db.get() as connection`, чтобы связанные изменения фиксировались либо откатывались вместе.

## Модель данных

| Таблица | Содержимое |
| --- | --- |
| `profiles` | Названия независимых бюджетов |
| `capitals` | Начальные суммы для пары профиль/валюта |
| `categories`, `tags` | Пользовательские справочники профиля |
| `entries` | Знаковая исходная сумма, валюта, необязательная сторона получения, время, комментарий и nullable-категория |
| `entry_tags` | Связи записей с тегами того же профиля |
| `auth_sessions` | Хеш токена, отпечаток пароля, CSRF-токен и выбранный профиль |
| `login_attempts` | Счётчик и начало окна ограничения по IP |

`entries.amount` — целые сотые: `> 0` для дохода, `< 0` для расхода и трансфера. Трансфер определяется наличием `destination_currency`; его `destination_amount` положительна, валюты различаются. Тип и курс не хранятся. Внешние ключи с `profile_id` предотвращают привязку чужих категорий и тегов.

`Entry` — представление для чтения, а не точная копия таблицы. `fetch_entries_for()` добавляет `kind`, отображаемую `category`, `tags` и `planned`. Суммы в `Entry` остаются знаковыми; поле формы получает модуль суммы. «Без категории» — представление `NULL`, отдельной строки в справочнике нет.

Удаление категории сначала устанавливает `category_id = NULL` её записям в той же транзакции. `ON DELETE SET NULL` для составного внешнего ключа не применяется: он обнулил бы также обязательный `profile_id`.

`fetch_balances()` и `calc_statistics()` принимают необязательный `now`, чтобы расчёт был воспроизводимым. При времени операции `<= now` запись текущая, при `> now` — плановая. Время хранится без смещения, в часовом поясе сервера. Периоды включают обе граничные даты; неделя — выбранная дата и шесть предыдущих дней.

## Контракты интерфейса

| HTML-атрибут или состояние | Назначение в `app.js` |
| --- | --- |
| `data-profile-switch` | Отправка формы выбора профиля |
| `data-period-form`, `data-period-date` | Переключение формы дня/недели/месяца/года/диапазона |
| `data-period-end`, `data-period-end-input` | Конечная дата активна только для диапазона |
| `data-confirm` | Текст подтверждения удаления; используется общий `dialog` |
| `data-entry-form`, `data-transfer-fields` | Форма операции и поля конвертации |
| `data-exchange-rate` | Поле курса **без `name`**, в POST не отправляется |
| `data-server-now`, `data-planned-note` | Пояснение будущей даты по времени сервера |
| `data-computed` | Курс вычислен из сумм; допускается повышенная точность отображения |
| `data-touched`, `data-error-id` | Посещённое поле и связанная через ARIA ошибка |

`parseFixed()` возвращает `bigint` масштабированного числа; `formatFixed()` восстанавливает десятичную строку. Точный курс удерживается парой `numerator`/`denominator`, поэтому изменение исходной суммы не использует округлённое отображение курса. `formatRate()` предназначен для показа. Отправленные суммы повторно проверяет сервер.

CSS использует `--accent` для основных действий, `--green`/`--red` для доходов/расходов, `--blue`/`--blue-line` для плановых данных. Цвета, размеры и компоненты прокомментированы рядом с определениями в `style.css`.

Основные семейства классов: `.sidebar`/`.nav-item` — навигация; `.panel`/`.panel-heading` — панели; `.balance-*`/`.summary-*`/`.breakdown-*` — показатели; `.entries-table`/`.entry-*` — журнал; `.form-*`/`.kind-selector`/`.tag-choices` — формы; `.transfer-*` — конвертация; `.planned-*` — плановые записи; `.field-invalid`/`.field-error` — валидация. `.sr-only` скрывает подпись визуально, сохраняя доступность.

Ячейка `.entry-title` должна оставаться табличной. Flex применяется только к вложенному `.entry-title-content`: иначе разделители строк разной высоты расходятся. До 760 px строки журнала становятся карточками, навигация — нижней панелью; дополнительные адаптации заданы для 1200, 1000, 370 и 1650 px. Переопределения в конце CSS сохраняют порядок каскада.

## Аннотации и проверки

Python использует встроенные generics, `TypedDict` для представлений и `TypeAlias` для псевдонимов. `cast()` на границе SQLite/Flask уточняет тип для анализатора и не выполняет проверку во время исполнения. В шаблонном контексте `Any` используется намеренно: значения разнородны. JavaScript проверяется в строгом режиме через JSDoc и `jsconfig.json`.

```bash
.venv/bin/python -m unittest discover -s tests -v
tsc --project jsconfig.json
```

При установленных mypy и `types-waitress` дополнительно:

```bash
mypy --strict --warn-unreachable main.py app tests
```

Pyright/BasedPyright берёт настройки из `pyrightconfig.json`. Если редактор не видит Flask/Werkzeug, проверьте установку `requirements.txt` и выбранное окружение `.venv`.
